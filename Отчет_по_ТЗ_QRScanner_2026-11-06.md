## 4. Что реализовано с ошибками

### 4.1. Сессия сканирования не разделяется между экранами (P0-1)

**Симптом:** пакетное сканирование добавляет коды, но список пуст; «Отправить» всегда пишет «Нет данных для экспорта».

**Причина:** каждый ViewModel создаёт **свой** `QRCodeRepository`:

- `ScanViewModel.java:19`
- `ListScannedViewModel.java:19`
- `SendViewModel.java:20`
- `MainViewModel.java:19`

Поле `sessionCodes` (`QRCodeRepository.java:20`) принадлежит экземпляру, а не приложению. Room-база — синглтон, а сессия — нет.

**Что делать:** сделать репозиторий синглтоном или вынести сессию в `ScanSession`; использовать один экземпляр во всех ViewModel. Детали — `PROJECT_ROADMAP.md`, `P0-1`.

### 4.2. Одиночный скан не попадает в список (P0-2)

**Симптом:** отсканировали один код → открылся список → он пуст.

**Причина:** в обычном режиме выполняется только `repository.insert(qrCode)` (`ScanViewModel.java:45-46`), а `ListScannedActivity` читает `sessionCodes` (`ListScannedActivity.java:66`).

**Что делать:** всегда добавлять скан в сессию и в БД либо перевести список на `LiveData` из Room.

### 4.3. Дубли в пакетном режиме (P0-3)

**Симптом:** один QR-код в кадре добавляется десятки раз.

**Причина:** `decodeContinuous` вызывает колбэк на каждом кадре (`ScanActivity.java:92-103`), а `handleScanResult` (`ScanActivity.java:137-140`) не проверяет, что код уже считан.

**Что делать:** дебаунс по значению и времени (1–2 секунды) или пауза сканера после успешного считывания.

### 4.4. Двойной запуск камеры (P0-4)

**Симптом:** камера может запускаться дважды, в Logcat возможны ошибки занятости камеры.

**Причина:** `startScanning()` вызывается из `onCreate` (`ScanActivity.java:149`), затем `onResume()` снова вызывает `barcodeView.resume()` (`ScanActivity.java:171-177`).

**Что делать:** единый метод запуска с флагом `scanningActive`; `pause()` сбрасывает флаг.

### 4.5. Удаление не синхронизировано с БД (P1-6)

**Симптом:** запись исчезает из списка, но остаётся в базе; `id` у сессионных кодов всегда 0.

**Причина:** `ListScannedViewModel.deleteCode()` вызывает только `removeSessionCode(position)` (`ListScannedViewModel.java:31-34`); `QRCodeRepository.insert()` не возвращает `id`.

**Что делать:** возвращать `id` из вставки, сохранять его в `QRCode`, при удалении вызывать `deleteById(id)`.

### 4.6. Список не возвращает в главное меню (ТЗ 2.3)

**Симптом:** кнопка «Назад» возвращает на экран сканирования, а не в главное меню.

**Причина:** `btnBackToList.setOnClickListener(v -> finish())` (`ListScannedActivity.java:60`) и `toolbar` тоже вызывают `finish()`. `ListScannedActivity` открывается из `ScanActivity`, поэтому `finish()` возвращает в сканер.

**Что делать:** добавить явный переход в `MainActivity` (например, `FLAG_ACTIVITY_CLEAR_TOP`) или переименовать кнопку в «Назад к сканированию».

### 4.7. JSON-инвентаризация работает частично

**Симптомы:**

- JSON с числовыми полями (`quantity`, `price`) не загружается;
- JSON с корневым объектом `{ "items": [...] }` не поддерживается;
- отображается только количество элементов, сами данные не видны;
- данные не доступны на экране `InventoryActivity`;
- файл читается без явной кодировки UTF-8.

**Причины:**

- `InventoryViewModel.java:50` использует `getString()`, который падает на числах;
- `InventoryViewModel.java:39` ожидает только `JSONArray`;
- `JsonInventoryActivity.java:36` создаёт отдельный ViewModel, а `InventoryActivity.java:25` — свой;
- `JsonInventoryActivity.java:61` показывает только `data.size()`;
- `JsonInventoryActivity.java:83` — `InputStreamReader` без кодировки.

**Что делать:** общий `InventoryRepository`, безопасный парсинг (`String.valueOf(item.opt(key))`), поддержка объекта, UTF-8, отображение списка.

### 4.8. Ручной ввод не имеет продолжения

**Симптом:** позиция добавляется, показывается Toast, но списка добавленных позиций нет; данные не сохраняются и не экспортируются.

**Причина:** `ManualInventoryFragment` добавляет элемент в `InventoryViewModel` (`ManualInventoryFragment.java:54-60`), но UI для отображения и сохранения отсутствует. ViewModel привязан к `InventoryActivity` и не разделяется с `JsonInventoryActivity`.

**Что делать:** показать список, добавить удаление/редактирование, сохранять в Room или общий репозиторий.

### 4.9. «Утверждённый формат» — пустой экран

**Симптом:** экран открывается, но список форматов не отображается.

**Причина:** `ArrayAdapter` создаётся (`ApprovedFormatFragment.java:42-46`), но никуда не устанавливается; `RecyclerView` получает только `LayoutManager` (`ApprovedFormatFragment.java:48`).

**Что делать:** реализовать `RecyclerView.Adapter`, подключить его, обработать выбор и сохранить выбранный формат.

### 4.10. Excel-экспорт: есть код, но сценарий не работает

**Симптомы:**

- экспорт выполняется в UI-потоке (`SendActivity.java:48`);
- `autoSizeColumn()` в POI использует `java.awt`, которого нет в Android (`ExcelExportService.java:58-60`) — риск падения;
- `id` в выгрузке всегда 0;
- файл сохраняется в приватный каталог и не отправляется;
- при пустой сессии кнопка Excel открывает фрагмент, где экспорт сразу отключён (`SendActivity.java:45-55`, `ExcelSendFragment.java:45-51`).

**Что делать:** фоновая задача, фиксированные ширины колонок, реальный `id`, `FileProvider` + `ACTION_SEND`, единый UX экрана.

### 4.11. 1С-экспорт: черновой формат

**Симптомы:**

- JSON создаётся, но структура не согласована с 1С;
- дата без часового пояса (`OneCExportService.java:35`);
- `id` всегда 0;
- файл не отправляется;
- нет проверки импорта на стороне 1С.

**Что делать:** согласовать формат, использовать ISO 8601 с часовым поясом, добавить шаринг и проверку.

### 4.12. MVVM реализован частично

**Симптомы:**

- Repository создаётся в каждом ViewModel → нет единого источника истины;
- Activity напрямую вызывает `ExcelExportService`/`OneCExportService` (`SendActivity.java:32-33,48,61`);
- сервисы показывают `Toast` (`ExcelExportService.java:72`, `OneCExportService.java:63`) — слой данных зависит от UI;
- часть логики находится в Activity (`ScanActivity`), а не в ViewModel.

**Что делать:** синглтон репозитория/сессии, экспорт через ViewModel/UseCase, результат — через `LiveData`/callback, без Toast в сервисах.

### 4.13. Фонарик и жизненный цикл

**Симптомы:** фонарик управляется отдельным `CameraManager` (`CameraHelper.java:40-54`), хотя камерой владеет ZXing; состояние кнопки не синхронизируется при повороте/возврате; нет гарантированного выключения на `onPause`.

**Что делать:** использовать `barcodeView.setTorchOn()/setTorchOff()`, синхронизировать текст кнопки, выключать при уходе с экрана.

### 4.14. Нефункциональные требования

| Требование | Симптом | Причина/файл |
|---|---|---|
| Разные разрешения | Не проверено на планшетах/landscape | Только `values/`, нет `layout-land`/`values-sw600dp` |
| Вращение | `ScanActivity` не поворачивается | `AndroidManifest.xml:37` |
| Обработка ошибок | Часть ошибок не обработана | Нет проверки `getExternalFilesDir() == null`, POI/AWT, недоступной камеры |
| Логирование по требованию | Логи всегда включены | `DebugLogger.java:7`, нет UI-переключателя |
| API 21+ | Фактически 26 | `app/build.gradle:11` |
| `provider_paths` | Открывает весь external storage | `res/xml/provider_paths.xml:3` |

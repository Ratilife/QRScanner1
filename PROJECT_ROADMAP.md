## 1. Краткое состояние проекта

**Что уже есть:**

- Компилируется, APK собирается (`app/build/outputs/apk/debug/app-debug.apk`, ~15,5 МБ).
- Работает камера и одиночное сканирование QR через ZXing.
- Есть Room-база для сохранения отсканированных кодов.
- Есть экраны: главное меню, сканирование, список, инвентаризация, JSON-инвентаризация, отправка.
- Есть запись файлов `.xlsx` и `.json` в приватный каталог приложения.

**Что не работает или работает частично:**

- Пакетное сканирование теряет коды при переходе в список.
- Одиночное сканирование не появляется в списке.
- Отправка в Excel/1С всегда видит «нет данных».
- Инвентаризация — каркас: данные не отображаются и не сверяются.
- «Утверждённые форматы» — пустой экран.
- Файлы экспорта не отправляются пользователю (нет шаринга).
- Нет тестов, CI и воспроизводимой сборки (в репозитории отсутствует Gradle Wrapper).
- В git закоммичены артефакты сборки `app/build/` (680 файлов).

**Итоговая оценка:** это рабочий каркас/MVP, а не готовый продукт. Основные пользовательские сценарии из README не проходят end-to-end.

## 5. Этап 1. Критические ошибки: сканирование, сессия, список

**Цель:** сценарий «Прочитать → список → отправить» должен работать end-to-end.

**Оценка:** 1–2 дня.
**Зависит от:** этапа 0.

### P0-1. Единый источник сессии

**Проблема:** `ScanViewModel`, `ListScannedViewModel` и `SendViewModel` создают каждый свой `QRCodeRepository`. Список `sessionCodes` живёт внутри экземпляра, поэтому данные не видны другим экранам.

**Что сделать (рекомендуемый минимальный вариант):**

- [ ] 1.1.1. Сделать `QRCodeRepository` синглтоном уровня приложения:
  ```java
  private static volatile QRCodeRepository INSTANCE;

  public static QRCodeRepository getInstance(Application application) {
      if (INSTANCE == null) {
          synchronized (QRCodeRepository.class) {
              if (INSTANCE == null) {
                  INSTANCE = new QRCodeRepository(application);
              }
          }
      }
      return INSTANCE;
  }
  ```
- [ ] 1.1.2. Заменить `new QRCodeRepository(application)` на `QRCodeRepository.getInstance(application)` в:
  - `ScanViewModel.java:19`
  - `ListScannedViewModel.java:19`
  - `SendViewModel.java:20`
  - `MainViewModel.java:19`
- [ ] 1.1.3. Сделать `sessionCodes` потокобезопасным (`CopyOnWriteArrayList` или `Collections.synchronizedList`).
- [ ] 1.1.4. (Рекомендуется) Отдавать наружу `LiveData<List<QRCode>>` и обновлять её при добавлении/удалении, чтобы UI не зависел от ручного `loadSessionCodes()`.

**Альтернатива (более правильная архитектурно):** вынести сессию в отдельный класс `ScanSession` (singleton + `MutableLiveData`), а `QRCodeRepository` оставить только для Room. Если выбираете этот путь — делайте его сразу для всех экранов, не смешивайте с вариантом выше.

**Критерии приёмки:**

- [ ] Код, добавленный в `ScanViewModel`, виден в `ListScannedViewModel` и `SendViewModel`.
- [ ] `getSessionCodes()` возвращает один и тот же список во всех трёх ViewModel.
- [ ] После перезапуска приложения сессия пуста (это ожидаемо до этапа 6).

### P0-2. Одиночный скан должен попадать в список

- [ ] 1.2.1. В `ScanViewModel.onQRCodeScanned(...)` всегда добавлять код в сессию:
  ```java
  repository.addSessionCode(qrCode);
  repository.insert(qrCode);
  ```
  (Или, если выбрана архитектура «список = БД», перевести `ListScannedActivity` на `getAllCodes()`.)
- [ ] 1.2.2. Явно зафиксировать в коде и README, что показывает список: текущую сессию или историю.
- [ ] 1.2.3. Обновлять список при возврате на экран (`onResume`) и после каждого изменения.

**Критерии приёмки:**

- [ ] Одиночный скан → открылся список → в нём ровно 1 запись с отсканированным значением.
- [ ] Пакетный скан 3 кодов → в списке 3 записи в порядке сканирования.
- [ ] Удаление записи из списка → осталось 2.
- [ ] Повторный вход в список не теряет и не дублирует записи.

### P0-3. Защита от дублей при непрерывном сканировании

**Проблема:** `decodeContinuous` вызывает колбэк на каждом кадре. Один код в кадре добавляется многократно.

- [ ] 1.3.1. Добавить в `ScanActivity` поля:
  ```java
  private String lastScannedValue;
  private long lastScannedAt;
  private static final long SCAN_COOLDOWN_MS = 2000;
  ```
- [ ] 1.3.2. В `handleScanResult(String value)`:
  ```java
  long now = System.currentTimeMillis();
  if (value.equals(lastScannedValue) && now - lastScannedAt < SCAN_COOLDOWN_MS) {
      return;
  }
  lastScannedValue = value;
  lastScannedAt = now;
  viewModel.onQRCodeScanned(value);
  ```
- [ ] 1.3.3. Сбрасывать `lastScannedValue` при смене режима и при возобновлении сканирования после паузы.
- [ ] 1.3.4. (Опционально) После успешного скана в одиночном режиме вызывать `barcodeView.pause()` и больше не сканировать до возврата на экран.

**Критерии приёмки:**

- [ ] Держим один QR-код в кадре 10 секунд → в списке ровно 1 запись.
- [ ] Два разных кода подряд → 2 записи.
- [ ] Повторное сканирование того же кода через 5 секунд → добавляется новая запись (это ожидаемо).

### P0-4. Убрать двойной запуск камеры

**Проблема:** `startScanning()` вызывается из `onCreate`, затем `onResume()` снова вызывает `barcodeView.resume()`.

- [ ] 1.4.1. Ввести один метод запуска и флаг состояния:
  ```java
  private boolean scanningActive = false;

  private void startScanning() {
      if (scanningActive) return;
      if (ContextCompat.checkSelfPermission(this, Manifest.permission.CAMERA)
              != PackageManager.PERMISSION_GRANTED) return;
      barcodeView.resume();
      scanningActive = true;
  }
  ```
- [ ] 1.4.2. В `onPause()`:
  ```java
  barcodeView.pause();
  scanningActive = false;
  ```
- [ ] 1.4.3. В `onResume()` вызывать только `startScanning()`.
- [ ] 1.4.4. В `onRequestPermissionsResult(...)` при успехе вызывать `startScanning()`, при отказе — сообщение и `finish()`.

**Критерии приёмки:**

- [ ] При первом открытии камера запускается один раз.
- [ ] В Logcat нет ошибок вида «Camera already in use» / «camera is being used».
- [ ] Сворачивание и возврат в приложение корректно возобновляют камеру.
- [ ] Отказ в разрешении показывает сообщение и закрывает экран без падения.
